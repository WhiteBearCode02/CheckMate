# Phase 1 별도 PC 런타임 검증표

이 문서는 **실행 예정 검증표**다. 아래 항목의 실제 기기·에뮬레이터 검증은 이번 개발 PC에서 수행하지 않았다. JVM 테스트 통과 및 APK 빌드는 화면 검증이나 Pleos 연결 검증을 대신하지 않는다.

## 준비

1. 개발자가 직접 `testDebugUnitTest`, `assembleDebug` 결과와 APK 생성 시각을 확인한다.
2. 모의 UI는 일반 Android API 28 이상 기기에서도 확인할 수 있다. 실제 SDK 검증은 Vehicle Service가 포함된 전용 Pleos Connect AVD에서 별도로 수행한다.
3. 테스트 차량은 안전하게 주차된 환경에서만 사용한다. 이 빌드에는 실제 차량 데이터 어댑터와 차량 제어 기능이 없다.
4. 화면 크기·밀도·글자 크기·Android 버전, APK 버전, SDK/서비스/AVD 버전을 기록한다.

## 화면과 흐름

- [ ] Debug 앱에서 `MOCK` 배지가 항상 보인다. 스마트폰 연결·녹화·실제 AI가 미연동으로 표시된다.
- [ ] 800×480 및 큰 가로 화면에서 잘림·겹침·스크롤 불가가 없다. 큰 글자 크기와 TalkBack에서도 버튼 설명과 순서를 확인한다.
- [ ] 모의 연결 성공, 실패, 데이터 없음, 미지원 상태가 구분된다. 값 없음이 0 km/h나 실제 정차로 표시되지 않는다.
- [ ] 모의 사고 버튼으로 UUID와 발생 시각이 생성되고 확인 화면이 열린다. 연속 입력이 같은 활성 사건을 중복 생성하지 않는다.
- [ ] 오탐 취소 후 현재 상태가 정상/대기로 돌아가고 기록에는 오탐 이력이 남는다. 다음 사건 ID가 이전과 다르다.
- [ ] 사고 확인 후 6개 대응 안내가 순서대로 제공된다. 안내 확인이 신고·영상 보존·보험 접수 완료로 표시되지 않는다.
- [ ] 대응 안내 완료 후 미연동 분석 결과에 비율이 없다. 명시적으로 선택한 Mock 예시에만 가상 비율과 주의 문구가 보인다.
- [ ] 사고 기록과 AI 화면에서 사건 ID가 일치하고 홈으로 돌아갈 수 있다.
- [ ] 회전/창 크기 변경 후 ViewModel이 유지되는 동안 활성 사건과 안내 진행 상태가 유지된다.
- [ ] 앱 프로세스를 종료하고 다시 열면 메모리 기록이 사라진다. 이 제한이 화면 안내와 일치한다.

## 주행 및 실패 제한

- [ ] 모의 주행 상태에서는 상세 기록·AI 화면 진입이 차단된다.
- [ ] 상세 화면이 열린 상태에서 provider가 주행·미연결·미확인 상태를 내보내면 상세 화면이 닫힌다. JVM 테스트 외 실제 갱신·레이아웃도 확인한다.
- [ ] 미연결·미지원·데이터 없음에서는 정차를 임의로 확정하지 않는다.
- [ ] Release 구성에서는 개발용 사고·연결 시나리오·Mock 분석 버튼이 없다. 기본 Pleos 세션은 미연동이며 연결 성공으로 보이지 않는다.
- [ ] 권한 거부·SDK 초기화 실패·SDK 종료 실패 시 앱이 종료되지 않는다. 실제 어댑터 추가 전에는 fake session JVM 테스트 범위임을 기록한다.
- [ ] 로그와 크래시 출력에 사건 객체·파일 참조·위치·SDK 예외 원문이 나타나지 않는다.
- [ ] 전화, 보험사 전송, 네트워크 요청, 외부 파일 접근, 유료 서비스 호출이 발생하지 않는다.

## 실제 Pleos 어댑터 추가 후에만 확인할 항목

기능별 지원 확인과 권한, 실제 값 수신, 지연·실패 콜백, 서비스 단절·재연결, 구독 해제, 종료 이후 콜백 차단을 검증한다. SDK 초기화 성공을 차량 데이터 연결 성공으로 해석하지 않는다. 세부 절차와 공식 자료는 [PLEOS_INTEGRATION.md](PLEOS_INTEGRATION.md)를 따른다.
