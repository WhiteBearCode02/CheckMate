# 사고 기록 동기화 정책 — Phase 3A

기준일: 2026-10-31. 구현 범위는 로컬 기록과 개발용 Fake Remote의 동기화 인터페이스다. 실제 Firebase·스마트폰 연결·백그라운드 네트워크 작업은 활성화하지 않는다.

## 신원과 데이터 범위

`ownerUserId`는 사고 소유권을 나타내며, 요청 본문만으로 접근 권한을 부여하지 않는다. Remote는 `Authentication`이 검증한 세션의 사용자 범위에서만 읽기·쓰기한다. 개발용 Fake도 같은 경계에서 권한 없는 세션과 다른 사용자의 기록을 거부한다. Fake는 실제 로그인·암호화 토큰·운영 보안 규칙의 대체가 아니다.

기기에는 `deviceId`, 사용자에는 `userId`, 사고에는 `eventId` UUID를 사용한다. 다른 사용자 소유의 같은 `eventId`가 존재하더라도 사용자 경계를 넘어 데이터를 반환하지 않는다. 로컬 기록의 소유권 변경은 일반 편집으로 취급하지 않으며 계정 전환·이관은 별도 검증이 필요하다.

## 버전과 재전송

| 값 | 의미 |
| --- | --- |
| `sync.localVersion` | 로컬 내용 변경 버전. 1부터 시작하며 동기화 중의 새 편집을 보호 |
| `sync.remoteVersion` | 마지막으로 반영한 원격 revision. 미전송 기록은 0 |
| `sync.modifiedAt` | UTC ISO 8601 수정 시각. 사용자 표시·추적용이며 충돌 승자를 결정하는 기준이 아님 |
| `sync.modifiedByDeviceId` | 마지막 수정 기기 UUID |
| operation ID | 사용자·기기·사고·로컬 버전에 대응하는 동일 작업 재전송 식별자. JSON 사고 본문과 분리된 Remote 호출 인자 |

쓰기 시 마지막으로 알고 있는 원격 버전을 함께 보낸다. Fake Remote는 일치할 때만 원자적으로 새 revision을 발급한다. 같은 operation ID의 재전송은 같은 payload·기대 revision일 때만 기존 결과를 재사용한다. 내용이 다른 재전송은 같은 작업으로 승인하지 않는다.

원격 응답을 기다리는 동안 로컬 편집이 발생하면 `AccidentSyncStore.applySync(expectedLocalVersion, record)`가 이전 버전의 응답 반영을 거부한다. 최신 로컬 내용을 지운 채 `SYNCED`로 표시하지 않고 다시 평가한다. 같은 사고의 원격 반복 수신은 `eventId`와 버전·내용을 기준으로 중복 행을 만들지 않는다.

## 상태

| `SyncStatus` | 의미 |
| --- | --- |
| `LOCAL_ONLY` | 로컬 전용. 전송 활성화나 실제 연결을 뜻하지 않음 |
| `PENDING` | 동기화가 필요한 로컬 변경 |
| `SYNCED` | 해당 Remote 구현과 버전 반영 완료. Fake에서는 개발용 검증만 의미 |
| `RETRY` | 일시적 연결 실패 등으로 로컬을 보존하고 재시도 필요 |
| `CONFLICT` | 자동 덮어쓰기를 중단한 상충 변경 |
| `BLOCKED` | 인증·설정 등 동기화 조건 미충족 |

현재 앱의 기본 상태는 로컬 저장이며 실제 스마트폰 연결·클라우드 성공을 표시하지 않는다. 재시도는 구현된 Coordinator 호출로 수행한다. OS 백그라운드 작업이나 실제 네트워크 상태 감시를 구현했다고 간주하지 않는다.

## 충돌 처리

모든 변경을 최신 `modifiedAt`으로 덮어쓰지 않는다. Phase 3A는 보수적으로 상충 내용을 `CONFLICT`로 남기며 자동 해결 UI·서버 중재는 후속 작업이다.

| 변경 성격 | 현재 정책 | 향후 승인된 해결 정책 |
| --- | --- | --- |
| 사고 확인 ↔ 오탐 취소 | 동시 상충 시 자동 전환 금지, 로컬 내용 보존·충돌 표시 | 사용자의 확인과 상태 전이 이력을 바탕으로 해결 |
| 삭제 ↔ 편집·증거 추가 | `deletedAt` tombstone 보존, 충돌 시 자동 부활·삭제 금지 | 소유자 확인 및 서버 보존 정책에 따라 해결 |
| 증거 추가 | `evidenceId` 중복 방지. 동시 다른 내용은 자동 합집합 없이 충돌 | 동일 ID 내용 일치·파일 소유권·동의 검증 후 합의된 병합 |
| 안내 확인·분석 결과 | 다른 버전의 상충 내용을 임의 합치거나 진행 단계를 되돌리지 않음 | 단계별 출처·분석 작업 ID·결과 버전 계약 후 해결 |
| 내용이 같은 재전송 | 기존 결과 재사용 또는 동기화 확인 | 새 사고·중복 증거를 생성하지 않음 |

삭제는 즉시 물리 제거가 아닌 `deletedAt` 표식이다. 다른 기기가 tombstone을 보기 전에 행을 지우거나 재수신된 과거 내용으로 부활시키지 않는다. 삭제 전파·보존 기간·영구 제거는 Phase 3B 운영 정책으로 합의해야 한다.


현재 revision이 맞더라도 발생 시각·차량 스냅샷·출처·생성자 변경, 사고 상태 역행, 기존 안내·증거 메타데이터 삭제/변경, 확정 분석 결과 교체, tombstone 부활은 거부한다. 사고 상태·순서 있는 안내 이력·분석 상태의 일관성도 검사한다. 정상적인 여러 오프라인 단계의 전진은 허용하되 최신 시각만으로 충돌을 해결하지 않는다.

## 오프라인·실패

사고 생성·안내 확인·기록 조회는 Remote 없이 로컬 Repository에서 처리한다. Fake 연결 실패는 기록을 삭제하지 않고 재시도 상태로 남긴다. 복구 후 같은 작업을 다시 보내도 중복 원격 revision·사고가 생기지 않아야 한다. 인증 실패나 버전 충돌을 단순 연결 실패로 숨기지 않는다.

실제 API는 인증 주체·서버 트랜잭션·접근 제어·오류 분류·재시도 제한을 검증한 후 연결한다. Phase 3A Fake의 네트워크 실패 모사는 실제 차량 무선망 장애·프로세스 강제 종료·서버 장애 검증을 대신하지 않는다.

## 파일·개인정보·외부 전송

동기화 대상은 [사고 JSON 계약](../../shared/contracts/README.md)의 메타데이터다. 원본 영상, 사진, 파일 URI, 위치 좌표, 보험사 개인정보, 키·토큰은 이 사고 envelope에 넣지 않는다. `READY_WITH_CONSENT` 값만으로 서버 업로드를 시작하지 않으며 동의와 접근 권한을 실제 전송 시 다시 확인해야 한다.

운영 Remote는 현재 비활성이다. 실제 클라우드 프로젝트·인증·보안 규칙·이용 조건·비용을 확인하고 사용자 승인 후 외부 전송을 별도로 활성화한다. Firebase 키나 서비스 계정을 저장소에 추가하지 않는다.

검증 결과와 미검증 항목은 [Phase 3 보고서](../../android-vehicle/docs/PHASE3_REPORT.md), 로컬 저장·복구는 [DB 설계](database-design.md)에 기록한다.
